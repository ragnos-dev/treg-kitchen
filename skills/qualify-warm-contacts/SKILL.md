# Qualify warm contacts

1. Ask who the user wants to reconnect with and what makes a contact relevant. Use any timeframe or account they specify. Use a named mailbox only after the user chooses it and authorizes the read.
2. In the user's own environment, inspect a bounded set of prior conversations. Prefer thread IDs, dates, participants and reply evidence. If the question requires reading message content, open only the relevant thread within the user's scope. Keep the evidence local.
3. Treat a genuine two-way exchange as a warm-contact signal. A newsletter, automated notice, one-way pitch, or mere address-book entry does not establish a relationship. Treat mass recipient lists and group threads conservatively. Record what the thread actually establishes.
4. Assess audience fit separately. Mark it confirmed only when the available evidence supports the user's stated criteria. Otherwise write “fit unknown” and identify what would settle it. Deduplicate by known contact address. Never merge people on name alone.
5. Return a private shortlist with contact, most recent evidence date, thread reference, reason the contact is warm, and fit or open question. Keep excluded and uncertain cases out of the confirmed shortlist. Let the user select candidates for any next step.
6. If the user wants public enrichment, show the proposed endpoint, input fields and per-contact volume first. Mailbox choice authorizes a source for this workflow. It does not authorize sending threads, addresses or the shortlist to Treg, publishing results, changing a CRM, or sending outreach.
